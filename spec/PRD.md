# PRD: SDV Simulator

> **제품**: SDV(Software Defined Vehicle) 시뮬레이터 — 차량 소프트웨어 플랫폼 시뮬레이션 환경
> **문서 종류**: 제품 요구사항 문서 (PRD)
> **상태**: v2 스테이지 승인 (T-002 게이트 통과, 2026-08-12)
> **날짜**: 2026-08-12
> **프로젝트 루트**: `/home/ubuntu/workspace/softwares/sdv-simulator`

---

## 1. 배경 및 문제 정의

SDV(Software Defined Vehicle)에서 차량의 기능은 하드웨어가 아닌 **소프트웨어**에 의해 정의된다.
차량 SW 개발자/아키텍트가 E/E 아키텍처, 차량 내 통신, 앱 런타임을 개발·검증하려면 물리적 하드웨어가 없어도
소프트웨어만으로 차량 플랫폼을 시뮬레이션할 수 있는 환경이 필요하다.

## 2. 목표 (Goals)

- 하드웨어 없이 차량 소프트웨어 플랫폼을 **정의 → 실행 → 검증**하는 시뮬레이터 제공
- 자동화·CI 연동이 가능한 **헤드리스 실행** (CLI) — v1 완료
- 코어 엔진을 **라이브러리**로 제공하여 테스트 하네스 등에 임베드 가능 — v1 완료
- 시뮬레이션 결과를 **웹 대시보드로 시각화·인터랙션** — v2 (이번 스테이지)
- 모든 아티팩트 형태(CLI/대시보드/데스크톱)가 **단일 코어 엔진을 공유**

## 3. 대상 청중 (Target Audience)

- **차량 SW 개발자/아키텍트**
  - E/E 아키텍처 설계 검증
  - 차량 내 통신(메시지 흐름·지연·대역폭) 동작 검증
  - 가상 노드 위에서 실행되는 앱/컴포넌트 테스트

## 4. 제품 범위 (Scope)

### 완료: v1 (1차 — 코어 + CLI)

| 영역 | 내용 |
|------|------|
| **E/E 아키텍처 모델링** | ECU/HPC 노드 정의, 토폴로지(노드 간 연결) 정의 |
| **차량 내 통신** | CAN/Ethernet 링크, 메시지 라우팅·지연·대역폭 시뮬레이션 |
| **앱 런타임** | 가상 ECU/HPC 위에서 SW 컴포넌트 실행 |
| **제공 형태** | 라이브러리 코어 + CLI |

### v2 (2차 — 이번 PRD의 대상): 웹 대시보드

| 영역 | 내용 |
|------|------|
| **동작 방식** | 로컬 웹 서버. **구조 뷰(다이어그램) 중심** — 브라우저에서 아키텍처·시나리오를 확인·편집·저장·실행 → v1 코어 엔진이 시뮬레이션 → 결과 시각화. 기존 JSON 이벤트 로그 파일 로드도 겸용. **파일은 브라우저가 직접 관리** (서버 저장 개념 없음 — F-11) |
| **구조 뷰 (기본 화면)** | 아키텍처 토폴로지 다이어그램 — YAML 파싱으로 노드(ECU/HPC)·링크(CAN/Ethernet)·게이트웨이·프레임을 **자동 렌더링**. **시뮬레이션 결과 오버레이 캔버스** 역할 겸함 |
| **편집·파일 관리** | 브라우저가 **로컬 파일 직접 읽기/쓰기** (Chrome/Edge: File System Access API — 같은 파일 저장 / Firefox/Safari: 업로드·다운로드 폴백). YAML 텍스트 편집 + **실시간 구조 미리보기 동기화** + 스키마 검증 피드백(v1 Pydantic 스키마 재사용) |
| **시뮬레이션 (구조 뷰 오버레이)** | 실행·재실행 → v1 코어 → **구조 뷰 위에서 리플레이**: 링크 위 프레임 전송 애니메이션, 노드 상태(태스크 실행·오버런·큐) 하이라이트, 게이트웨이 라우팅·스위치 드롭 표시. 재생/일시정지/탐색 컨트롤 + 보조 타임라인·이벤트 상세 패널 (구조 뷰와 클릭 연동) |
| **제공 형태** | 기존 패키지에 대시보드 서버 명령 추가 (예: `sdv-sim serve`) — 세부는 ASR/ADR에서 확정 |

### v3 (3차 — 연기 가능)

- 데스크톱 앱 (가벼운 셸 형태)

### 후속 후보 (스테이징 미정)

- OTA: 업데이트 캠페인, 버전 관리, 배포 흐름 — **v2에는 포함하지 않음 (사용자 확정)**

## 5. 비목표 (Out of Scope — v2 제외)

- 차량 동역학/물리 시뮬레이션
- ADAS/자율주행 시나리오·센서 시뮬레이션
- OTA (업데이트 캠페인·버전 관리·배포 흐름) — v2 미포함 (사용자 확정, 후속 후보)
- 실제 하드웨어 연동 (HIL — Hardware-in-the-Loop)
- 데스크톱 앱 (v3로 연기)
- 실시간/안전 필수(Safety-Critical) 인증 지원
- 클라우드 배포·다중 사용자·계정 인증 (로컬 실행 전용 — **단, `--host 0.0.0.0`으로 외부 접근은 단일 사용자 한정 허용**, serve-network-binding, 2026-08-13)
- 구조화 폼(폼 기반) 편집 — v2는 YAML 텍스트 편집 기반 (스키마 검증 피드백 제공)
- 시각적(드래그 앤 드롭) 아키텍처 편집 — 구조 뷰는 조회·동기화 전용, 편집은 YAML 텍스트 (후속 후보)
- 브라우저에서의 파일 삭제·이름 변경 — 미지원 (로컬 파일 관리 도구 사용)

## 6. 제약 조건 (Constraints)

- 문서·CLI·대시보드 UI 출력은 한국어/영어 모두 지원 가능한 구조 (v1 i18n 구조 재사용)
- 시뮬레이션 결과는 자동화 검증(assertion)에 사용 가능해야 함 — v1 유지
- 확장성: v3(데스크톱)가 코어 변경 없이 추가될 수 있는 경계(boundary) 설계 — v1 유지
- 대시보드는 **v1 코어를 백엔드로 재사용** — YAML 문자열 입력 API(`loads()`) 추가만 허용, 기존 공개 API 계약은 하위 호환 유지 (core-yaml-string-input, 2026-08-12)
- 로컬 실행 전용 (단일 사용자·단일 머신, 웹 브라우저 접속) — **`--host` 옵션으로 외부 접근 가능하며, 이 경우 인증이 없어 네트워크 보호(방화벽 등)는 사용자 책임** (serve-network-binding, 2026-08-13)
- 파일 접근은 **브라우저 권한 경계** (서버 파일시스템 접근 없음 — F-11, dashboard-browser-file-access)

## 7. 성공 기준 (Success Criteria — v2)

1. 사용자가 브라우저에서 아키텍처 구조를 다이어그램으로 확인하고, 정의를 편집·저장·시뮬레이션 실행할 수 있다.
2. 실행 결과가 **구조 뷰(토폴로지) 위에서** 메시지 흐름·노드 상태로 리플레이된다.
3. 필터·상세 조회·재실행 등 인터랙션이 가능하다.
4. assertion 결과와 drop/overrun/버스 부하 리포트를 대시보드에서 확인할 수 있다.
5. 위 모든 작업이 v1 코어의 **공개 API 계약을 유지**하면서 수행된다 (YAML 문자열 입력 API `loads()` 추가는 허용 — core-yaml-string-input).
6. 편집 중 스키마 검증 피드백을 받을 수 있고, 저장 시 **브라우저 로컬 파일**에 반영된다 (Chrome/Edge = 같은 파일, 기타 = 다운로드).
