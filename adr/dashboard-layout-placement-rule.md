# 자동 레이아웃 배치 규칙 (layout-placement-rule)

## Concern
구조 뷰 자동 레이아웃의 "노드 타입(ECU/HPC)·링크 종류(CAN/Ethernet) 기준 배치"를 **검증 가능한 구체 규칙**으로 무엇으로 할 것인가?

## Status
approved

## Context
- v2 spec (구조 뷰 렌더링·성능, M-5): "자동 레이아웃 적용 — 노드 타입(ECU/HPC)·링크 종류(CAN/Ethernet) 기준 배치, **결정적**: 동일 입력(동일 YAML) → 동일 좌표. 구현은 고정 시드 + 고정 반복 수의 D3 포스 또는 계층 레이아웃 중 생성자 선택"
- 결정성("동일 YAML → 동일 좌표")은 테스트 가능하지만, "타입·링크 종류 기준 배치"는 **배치 규칙이 명시되지 않아 검증 불가** — 생성자가 타입 기준을 무시해도 fail 판정 불가 (spec review F-6)
- ASR-016 — M-5 레이아웃 결정성 ADR의 downstream concern "레이아웃 기준 구체화 — spec 인코딩"이 미해소 상태로 잔존
- v1 의미론: 게이트웨이는 **인프라**(명시적 노드가 아닌 라우팅 엔티티). 노드 = `ECU|HPC`, 링크 = `can|ethernet`
- 렌더링 스케일: 노드 ≤ 200 / 링크 ≤ 500 (v2 구조 뷰 — v1 시뮬레이션 스케일과 별개 차원)

## Decision
**Option A — 타입 밴드 레이아웃 (Type-band layout)** (2026-08-12 사용자 승인 "Option A로 확정"): 노드를 타입별 수평 밴드(HPC 상단 / 게이트웨이 중앙 / ECU 하단)로 배치하고, 밴드 내 순서는 결정적 규칙(연결 링크 수 내림차순 → 이름 사전순)을 사용한다. 링크 종류(CAN/Ethernet)는 시각적 속성(색·굵기·대시)으로 구분한다. "타입 기준 배치"를 검증 가능한 명시 규칙으로 만들고 결정성을 구조적으로 보장.

## Options
### Option A — 타입 밴드 레이아웃 (Type-band layout)
- 노드를 **타입별 수평 밴드**로 배치: HPC 밴드(상단) / 게이트웨이 밴드(중앙) / ECU 밴드(하단). 게이트웨이는 링크 간 라우팅 엔티티이므로 중앙 배치
- 밴드 내 노드 순서는 **결정적 규칙** (예: 연결 링크 수 내림차순 → 이름 사전순)
- 링크 종류(CAN/Ethernet)는 **시각적 속성**(색·굵기·대시)으로 구분 — 위치와 무관
- Pro: "타입 기준"이 직접 관찰 가능(검증 쉬움 — "같은 타입 노드는 같은 밴드", "게이트웨이는 중앙"), 결정성이 구조적으로 보장, 구현 단순
- Con: 대형 그래프(≤200노드)에서 단일 밴드 내 밀집 가능, 유기적 배치 대비 미관 한계

### Option B — 결정적 포스 + 타입 클러스터 제약 (Deterministic force with type clustering)
- 고정 시드 + 고정 반복 수의 D3 포스 + **타입 기반 포스**(동일 타입 인력, 이종 타입 척력) + **링크 종류별 스프링 길이 차이**(CAN 짧게 / Ethernet 길게)
- Pro: 유기적 배치 품질, 200노드 적응성
- Con: "타입 기준 배치"가 명시적 규칙이 아니라 **결과적 특성** — 검증이 간접 지표(동형 노드 중심 거리 등)에 의존, 결정성 보장이 구현에 민감(타이브레이크·부동소수점)

### Option C — 커넥티비티 계층 레이아웃 (Connectivity/gateway-centric layers)
- 게이트웨이를 중심으로 **연결 홉 기준 계층 배치**(게이트웨이 직결 노드 → 1홉 → 2홉…). 노드 타입은 계층 내 배열 순서로만 사용
- Pro: 라우팅 중심 토폴로지(게이트웨이-링크 구조)를 자연스럽게 반영, 결정적
- Con: "타입 기준"이 주 규칙이 아니어서 스펙 문구("노드 타입 기준 배치")와 약한 정합, 게이트웨이 없는 토폴로지에서 계층 근거 상실

## Tradeoffs
| 차원 | A (타입 밴드) | B (포스+타입) | C (커넥티비티) |
|------|--------------|---------------|----------------|
| "타입 기준" 검증 가능성 | ★★★ (명시 규칙) | ★★ (간접 지표) | ★ (타입은 부차적) |
| 결정성 보장 | ★★★ (구조적) | ★★ (구현 민감) | ★★★ |
| 대형 그래프(200노드) 품질 | ★★ (밴드 내 밀집) | ★★★ | ★★ |
| 구현 단순성 | ★★★ | ★★ | ★★ |
| 게이트웨이 구조 반영 | ★★ (중앙 밴드) | ★★ | ★★★ |

## Recommendation
- **Option A** 권장. 스펙의 "타입 기준 배치"를 **검증 가능한 규칙**으로 만들고 결정성을 구조적으로 보장. 게이트웨이를 중앙 밴드로 두는 것은 v1의 "게이트웨이 = 인프라" 의미론과 정합. 링크 종류 구분은 시각 속성으로 명시. 대형 그래프 밀집 문제는 생성 시 밴드 내 서브레이아웃(다열 배치·겹침 방지)으로 완화 가능.

## Consequences
- spec 인코딩(예정): "타입 밴드(ECU/HPC/게이트웨이) 배치 + 밴드 내 결정적 순서 규칙 + 링크 종류 시각 구분 + 동일 YAML → 동일 좌표"로 구체화
- 검증 가능 항목: "같은 타입 노드는 같은 밴드", "게이트웨이는 중앙 밴드", "동일 입력 → 동일 좌표", "CAN/Ethernet 시각 구분"
- 명시적 배제: 비결정적 D3 포스, YAML 좌표 필드 추가
