# 자동 레이아웃 결정성 (layout-determinism)

## Concern
구조 뷰의 자동 레이아웃을 **결정적**(동일 YAML → 동일 좌표)으로 요구할 것인가?

## Status
approved

## Context
- v2 spec: "자동 레이아웃 적용 — D3 기반, 노드 타입(ECU/HPC)·링크 종류(CAN/Ethernet) 기준 배치" — 배치 규칙이 추상적 (spec review M-5).
- D3 포스 레이아웃은 기본 비결정적(난수 초기화) — 같은 YAML이라도 새로고침/재실행마다 노드 위치가 바뀌면 리플레이 오버레이·클릭 기억·스크린샷/문서 공유가 불안정.
- ADR topology-rendering-performance의 downstream concern "자동 레이아웃 배치 규칙 — Spec 인코딩"이 미해소 상태로 전달됨.
- 구조 뷰는 리플레이 오버레이의 캔버스 역할 — 위치 안정성이 UX의 전제.

## Options
### Option A — 결정성 요구 (권장)
- spec에 "동일 입력 → 동일 레이아웃(결정적)"을 요구사항으로 명시. 구현은 자유 — 결정적 계층 레이아웃 또는 고정 시드 + 고정 반복 수의 포스 레이아웃.
- Pro: 리플레이 오버레이 안정 / 클릭·선택 유지 / 스크린샷·문서 재현성 / 테스트 용이
- Con: 비결정적 포스 대비 최적 배치에서 다소 떨어질 수 있음

### Option B — 비결정적 포스 허용
- 표준 D3 force 레이아웃, 매 로드 시 재계산.
- Pro: 유기적 배치, 구현 단순
- Con: 새로고침/재실행마다 위치 변경 — 오버레이·클릭 기억·스크린샷 불안정, v2 핵심 UX(구조 뷰 위 리플레이) 손상

### Option C — 고정 규칙 배치 (포스 없음)
- 노드 타입·링크 종류로 그리드/밴드 고정 배치.
- Pro: 완전 결정적·예측 가능
- Con: 대형 그래프(200노드) 적응성 낮음, 미관 하락 가능

## Tradeoffs
| 차원 | A (결정성 요구) | B (비결정적) | C (고정 규칙) |
|------|-----------------|--------------|---------------|
| 오버레이 안정성 | ★★★ | ★ | ★★★ |
| 배치 품질(대형 그래프) | ★★ (구현에 따라) | ★★★ | ★ |
| 구현 단순성 | ★★ | ★★★ | ★★ |

## Recommendation
- **Option A** 권장. 결정성 요구를 스펙에 명시하고 구현 방식(고정 시드 포스·계층 레이아웃)은 생성자가 선택 — 안정성 요구를 지키면서 구현 자유를 유지.

## Consequences
- spec에 "동일 입력 → 동일 레이아웃(결정적)"을 요구사항으로 명시
- 구현 방식은 생성자 선택 — 결정적 계층 레이아웃 또는 고정 시드 + 고정 반복 수의 포스 레이아웃
- 배치 규칙 기준(노드 타입 ECU/HPC·링크 종류 CAN/Ethernet)과 대형 그래프(≤200노드) 품질 목표는 생성 시 검증
