# Serve Network Binding (외부 접근)

## Concern
`sdv-sim serve`가 어떤 네트워크 인터페이스에 바인딩되어야 하는가? 외부 브라우저(인터넷)에서 `http://161.33.194.12:8888` 접근을 지원할 것인가?

## Status
approved

## Context
- 현재 `serve.py` L29: `HOST = "127.0.0.1"` — 루프백 전용, 같은 머신 브라우저만 접속 가능
- v2 스펙 제약: "로컬 실행 전용(단일 사용자·단일 머신, 브라우저 접속)" / Out of Scope: "클라우드 배포·다중 사용자·계정 인증"
- 사용자 요청(2026-08-13): 외부 브라우저에서 `http://161.33.194.12:8888` 접근 희망, **8888 포트는 이미 방화벽에서 열어 둠**
- 서버 공인 IP: `161.33.194.12` (사설망 `10.0.0.45/24` 뒤), sshd 실행 중
- 대시보드는 **인증 메커니즘이 없음** (스펙상 단일 사용자 가정) — 외부 노출 시 정보 노출 리스크 존재

## Decision
**Option B — `--host` 옵션 추가 (기본 127.0.0.1, 선택 시 0.0.0.0)**
사용자 승인 (2026-08-13, 응답 "1"). 외부 브라우저 직접 접근(`http://161.33.194.12:8888`)을 지원하면서 기본 동작(루프백) 안전성은 유지한다. 스펙 Constraint·CLI 옵션 절 수정, ASR-019 Resolution 갱신이 수반된다.

## Options
### Option A — SSH 터널 유지 (변경 없음)
- 외부 PC에서 `ssh -L 8888:127.0.0.1:8888 ubuntu@161.33.194.12` → 로컬 `http://localhost:8888`
- Pro: 코드·스펙 무변경, 안전 (서버가 네트워크에 노출되지 않음), 인증 문제 없음
- Con: 브라우저 주소가 `161.33.194.12:8888`가 아님 (터널 설정 필요), SSH 접근 권한 있는 사용자만 사용 가능

### Option B — `--host` 옵션 추가 (기본 127.0.0.1, 선택 시 0.0.0.0)
- `sdv-sim serve --host 0.0.0.0`으로 바인딩 확장, 기본값은 루프백 유지
- Pro: 사용자가 원하는 `http://161.33.194.12:8888` 직접 접근 가능, 기본 동작(안전)은 유지
- Con: 스펙 제약("로컬 실행 전용") 수정 필요, **인증 없는 서버가 인터넷에 노출** — 방화벽으로만 보호 (현재 8888 개방됨)

### Option C — HOST 상수 0.0.0.0 하드코딩
- `serve.py` L29을 `0.0.0.0`으로 영구 변경
- Pro: 옵션 추가 없이 즉시 외부 접근
- Con: 모든 실행에서 네트워크 노출 (실수로라도), 기본값 안전성 상실, 비문서화 변경 — 비권장

## Tradeoffs
| | Option A (SSH 터널) | Option B (--host 옵션) | Option C (하드코딩) |
|---|----------|----------|----------|
| 외부 브라우저 직접 접근 | ✗ (localhost 경유) | ✓ (`161.33.194.12:8888`) | ✓ |
| 스펙 변경 | 없음 | 필요 (Constraint 수정) | 위반 (무문서화) |
| 보안 리스크 | 낮음 | 중간 (인증 없음 + 방화벽 의존) | 높음 (항상 노출) |
| 코드 변경 | 없음 | 작음 (CLI 옵션 1개) | 작음 (상수 1줄) |
| 다중 사용자 안전성 | ✓ (SSH 인증) | ✗ (아무나 접속) | ✗ |

## Recommendation
- **Option B 권장** — 사용자 요구(외부 브라우저 직접 접근)를 충족하면서 기본 동작 안전성은 유지. 단, 노출 리스크가 있으므로 스펙에 "외부 노출 시 보호 조치 필요"를 명시하고, 필요하면 `--host` 사용 시 경고 문구 출력을 함께 고려.

## Consequences
- Option B 채택 시: `serve.py`에 `--host` 옵션 추가, 스펙 Constraint·Out of Scope·CLI 옵션 절 수정, ASR-019 Resolution 갱신
- 무엇을 하지 않는가: 다중 사용자·계정 인증 추가는 여전히 Out of Scope (이번 결정 범위 아님)
