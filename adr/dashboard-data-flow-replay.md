# 대시보드 데이터 흐름·리플레이 모델

## Concern
대시보드가 시뮬레이션 데이터를 어떻게 획득하고, 구조 뷰 오버레이 리플레이(재생/일시정지/탐색)에 어떻게 전달할 것인가?

## Status
approved

## Context
- v2 동작 방식 = 로컬 웹 서버 + "파일 로드 겸용" — YAML에서 실행하거나 기존 이벤트 로그 파일을 열어 구조 뷰에서 리플레이 (PRD v2).
- v1 코어 API 계약(`load`/`run`/`events`) 유지 필수 (ASR-006, PRD 제약 "v1 코어 무변경"). v1은 이벤트 로그를 JSON으로 출력.
- 기술 스택 = FastAPI + React/TS (ASR-014). serve = 단일 프로세스 (ASR-019).
- 성능 목표: 대용량 이벤트 ≤100만 (v1 성능 목표와 정합).
- 리플레이 요구: 재생/일시정지/탐색(시크) — PRD 성공 기준 3.

## Decision
**Option A — 코어 임베드 실행 + 일괄 JSON 전달**
사용자 승인("좋아"): 서버가 v1 코어를 동일 프로세스에 import해 실행(또는 로그 파일 로드) → 타임스탬프 정렬 전체 이벤트 목록을 `GET /api/events`로 반환. 리플레이는 프런트엔드 로컬 재생/시크.

## Options
### Option A — 코어 임베드 실행 + 일괄 JSON 전달 (권장)
- 실행 흐름: 서버(FastAPI)가 `sdv_sim` 코어를 **동일 프로세스에 import**, v1 공개 API(`load`/`run`)로 시뮬레이션 실행 → 이벤트 목록 생성. 파일 로드 흐름: 기존 이벤트 로그 JSON을 읽어 동일한 이벤트 목록 구성. 두 흐름 모두 하나의 API(`GET /api/events`)로 타임스탬프 정렬 전체 목록을 프런트엔드에 반환.
- 리플레이: 프런트엔드가 전체 이벤트를 보유하고 **로컬에서 재생/일시정지/시크** — 탐색 지연 없음(임의 시각 점프 즉시).
- Pro: 구현 단순 / v1 공개 API 그대로(코어 무변경 보장) / 단일 프로세스(ASR-019와 일관) / 시크 UX 최고 / 로그 파일 로드와 실행이 동일 파이프라인
- Con: 대용량(≤100만)일 때 응답 JSON 크기·파싱 비용(수십~수백 MB) — 서버 메모리에 전체 보유 필요

### Option B — 코어 임베드 실행 + SSE 스트리밍
- 실행은 A와 동일하되, 이벤트를 청크 단위 SSE로 push — 프런트엔드가 버퍼링하며 재생.
- Pro: 초기 응답 지연 감소, 실행 진행과 리플레이 시작이 자연스럽게 연결
- Con: 시크 시 서버 왕복(청크 재요청) 필요, 커넥션 상태 관리 복잡, 로컬 단일 사용자 시나리오에서 이점 제한적, 프런트엔드 버퍼링 로직 추가

### Option C — CLI subprocess 실행 + 일괄 JSON
- 서버가 `sdv-sim run`을 **하위 프로세스로 실행**, 생성된 이벤트 로그 JSON을 읽어 전달.
- Pro: 프로세스 격리(코어 크래시가 서버에 영향 없음), CLI 출력(진행률·리포트) 재사용
- Con: 프로세스 관리·로그 경로 처리 복잡, 실행 상태(진행률) 전달 추가 필요, v1 공개 API 인프로세스 호출보다 간접적

## Tradeoffs
| 차원 | A (임베드+일괄) | B (임베드+SSE) | C (subprocess) |
|---|------|------|------|
| v1 코어 무변경 보장 | ★★★ (공개 API import) | ★★★ | ★★ (프로세스 간접) |
| 구현 단순성 | ★★★ | ★★ | ★★ |
| 시크 UX | ★★★ (즉시) | ★★ (서버 왕복) | ★★★ |
| 대용량 메모리 | ★★ | ★★★ (청크) | ★★ |
| 단일 프로세스 정합 (ASR-019) | ★★★ | ★★★ | ★★ |

## Recommendation
- **Option A** 권장. 로컬 단일 사용자 + 탐색 중심 UX에 가장 적합하고, v1 공개 API 재사용으로 "코어 무변경" 제약을 직접 보장. 대용량 이벤트는 서버측 프로젝션(리플레이용 축약 이벤트)으로 완화 가능 (ASR-016과 연결).

## Consequences
- 서버는 실행·파일 로드 모두에서 이벤트 목록을 메모리에 보유 (프로젝트 루트 내 로그 파일 기반).
- 이벤트는 타임스탬프 정렬 배열로 프런트엔드에 전달 — 리플레이 애니메이션은 프런트엔드 로컬 렌더링.
- SSE/WebSocket 스트리밍은 비목표 (로컬 전용에서 과잉).
